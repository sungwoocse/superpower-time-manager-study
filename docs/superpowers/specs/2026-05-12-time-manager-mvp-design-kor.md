# 시간 관리자 MVP 설계

## 목표

Windows 우선의 데스크탑 시간 관리 앱을 만든다. 첫 버전은 브라우저 웹사이트 사용 시간을 기록하고 생산성 통계를 보여주는 데 집중한다. 사이트 차단, 알림, 동기화, macOS 지원은 첫 버전에 포함하지 않는다.

## 제품 범위

MVP는 브라우저 확장 프로그램과 Windows 데스크탑 앱으로 구성한다.

- 브라우저 확장 프로그램: Chrome과 Edge 계열 브라우저의 활성 탭 URL을 읽는다.
- Windows 데스크탑 앱: 사용 이벤트를 받고, 로컬 기록을 저장하고, 도메인을 분류하고, 통계를 보여준다.
- 로컬 데이터베이스: 모든 사용 기록과 분류 규칙을 사용자 PC 안에 저장한다.

MVP에서 제외하는 범위:

- 사이트 차단.
- 시간 제한 알림.
- 클라우드 동기화 또는 계정.
- macOS 지원.
- VS Code, 게임, 메신저, Notion 데스크탑 같은 일반 데스크탑 앱 추적.

## 권장 아키텍처

데스크탑 앱은 Tauri, React, TypeScript, SQLite를 사용한다. 브라우저 확장 프로그램은 Chrome과 Edge를 지원하는 Chromium 확장으로 만든다.

Tauri는 Electron보다 앱 크기와 리소스 사용량을 줄이기 좋아서 Windows 유틸리티 형태의 MVP에 적합하다. React와 TypeScript는 UI 구현에 실용적이고, SQLite는 별도 서버 없이 로컬 데이터를 안정적으로 저장하기에 충분하다.

## 구성 요소

### 브라우저 확장 프로그램

확장 프로그램은 활성 탭 변경, URL 변경, 브라우저 포커스, 가능한 경우 idle 상태 변화를 감지한다. 감지한 정보를 정규화된 사용 이벤트로 데스크탑 앱에 보낸다.

초기 이벤트 필드:

- `url`
- `domain`
- `title`
- `browser`
- `eventType`
- `timestamp`

확장 프로그램은 브라우징 기록 전체를 보내지 않는다. 시간 추적에 필요한 활성 사용 이벤트만 전송한다.

### 데스크탑 앱

데스크탑 앱은 메인 사용자 인터페이스와 로컬 데이터 계층을 담당한다.

주요 화면:

- 대시보드: 오늘의 생산적, 비생산적, 중립 사용 시간.
- 사이트: 사이트별 사용 시간과 분류.
- 추세: 간단한 주간 사용 시간 차트.
- 규칙: 사용자가 수정할 수 있는 도메인 분류 규칙.

첫 화면은 랜딩 페이지가 아니라 대시보드여야 한다.

### 로컬 수집 API

확장 프로그램은 데스크탑 앱과 통신할 로컬 경로가 필요하다. MVP의 기본 방식은 앱이 실행 중일 때 Tauri sidecar 또는 Rust 백엔드가 로컬 HTTP 엔드포인트를 여는 것이다.

로컬 엔드포인트는 활성 사용 이벤트를 받고, 검증하고, 도메인을 분류하고, SQLite에 사용 구간을 기록한다.

Native messaging은 초기 구현 범위에 포함하지 않는다. 다만 확장 프로그램의 전송 계층은 분리해서, 나중에 패키징이나 보안 요구가 생기면 local HTTP를 native messaging으로 교체할 수 있게 한다.

### 저장소

SQLite 테이블:

- `usage_events`: 확장 프로그램에서 받은 정규화된 원본 이벤트.
- `usage_sessions`: 계산된 활성 사용 시간 구간.
- `domain_rules`: 사용자가 수정할 수 있는 도메인 분류 규칙.

분류 값:

- `productive`
- `unproductive`
- `neutral`

초기 기본 규칙:

- 생산적: `chatgpt.com`, `chat.openai.com`, 사용자가 추가한 Codex 도메인.
- 비생산적: `youtube.com`, `instagram.com`.
- 중립: 매칭되지 않은 모든 도메인.

## 데이터 흐름

1. 사용자가 브라우저 탭에 포커스를 둔다.
2. 확장 프로그램이 활성 탭 URL과 시각을 감지한다.
3. 확장 프로그램이 사용 이벤트를 데스크탑 앱으로 보낸다.
4. 데스크탑 앱이 이벤트를 검증하고 정규화한다.
5. 데스크탑 앱이 이전 활성 구간을 닫고 현재 구간을 열거나 갱신한다.
6. 데스크탑 앱이 `domain_rules`를 기준으로 도메인을 분류한다.
7. UI는 SQLite에서 집계 데이터를 읽어 대시보드와 추세 화면에 표시한다.

## 시간 추적 규칙

앱은 활성 브라우저 사용 시간만 계산한다. 다음 상황에서는 시간을 멈추거나 일시 중지한다.

- 브라우저가 포커스를 잃음.
- PC가 idle 상태가 됨.
- 활성 탭에 유효한 URL이 없음.
- 확장 프로그램이 데스크탑 앱에 연결할 수 없음.

이벤트가 늦게 도착하거나 순서가 어긋나면, 비현실적인 사용 시간이 생기지 않도록 해당 구간을 제한하거나 무시한다.

## 오류 처리

데스크탑 앱이 실행 중이 아니면 확장 프로그램은 작은 인메모리 큐를 유지하고 잠시 재시도한다. MVP에서는 확장 프로그램 쪽의 영구 오프라인 버퍼링은 구현하지 않는다.

로컬 수집 엔드포인트가 이벤트를 거부하면, 사용자에게는 조용히 실패하고 진단 정보는 확장 프로그램 콘솔에서만 확인할 수 있게 한다.

데이터베이스를 사용할 수 없거나 손상된 경우, 데스크탑 앱은 명확한 로컬 오류 상태를 보여주고 기존 데이터를 자동 삭제하지 않는다.

## 개인정보

모든 데이터는 로컬에 남는다. 앱은 사용 기록을 외부 서버로 보내지 않는다.

UI에서는 기록이 로컬에 저장된다는 점을 명확히 보여준다. MVP에는 계정 생성, 텔레메트리, 원격 분석을 포함하지 않는다.

## 테스트 전략

통계를 망가뜨릴 가능성이 큰 동작을 중심으로 테스트한다.

- 도메인 정규화.
- 분류 규칙 매칭.
- 사용 시간 구간 생성과 종료.
- 일별 및 주별 집계.
- 중복, 누락, 순서가 어긋난 이벤트 처리.

수동 검증 항목:

- Chrome 활성 탭 추적.
- Edge 활성 탭 추적.
- 데스크탑 앱이 실행 중일 때와 실행 중이 아닐 때.
- 생산적, 비생산적, 중립 사이트 간 전환.

## 구현 메모

전송 계층, 분류 로직, 저장소 로직, UI 집계 로직은 분리한다. 확장 프로그램은 사이트가 생산적인지 판단하지 않는다. 사용자 규칙이 일관되게 적용되도록 분류 책임은 데스크탑 앱이 가진다.

MVP에서는 알림, 제한, 차단, 데스크탑 전체 앱 추적을 구현하지 않는다.
